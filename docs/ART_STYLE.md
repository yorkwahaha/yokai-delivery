# Yokai Delivery｜場景美術統一規格

版本 2.0｜2026-10-21｜**現行新圖製作標準**。新使用者明確指示優先；此規範取代 10/15 舊版中「地面必須預烘斜角」及舊長檔名規則，**不追溯重命名既有素材**。

## 1. 目標與已決策
- 八關共用同一套：**半水墨 × 半浮世繪 × 強墨線 × 和紙木版印痕 × 克制色彩**；場景可有濕潤、霧氣、幽異感，但不能變成照片寫實、3D擬真、現代向量或兒童超Q。
- 遊戲 Canvas2D，現有偽 2.5D `tilt=0.60`，可切 2D。**0.60 是引擎投影參數，不等於要求生圖固定 45° 俯角**；「Hades 式鏡頭感」是整體最終畫面觀感，不能預先把地板變形成斜視場景又再投影一次。
- **Stage2 stone_v3**（深藍濕石板、自然不規則石形、粗墨縫）作**畫風和石板語言參考**，**不是直接作無限平鋪的已合格母版**；此前 stone_v2 鵝卵石感、stone_v3 強透視／接縫重複、Method-B ART_FAIL 均不能冒稱成功。
- 原先 ChatGPT 第一批八張三聯地板是 **A 組喜歡的候選**、第二批四張 **淘汰**；Nano Banana 2.1 的八張三聯 **B 組為候選**。不得將三聯概念圖等同可用 tile，不得虛構 A/B 最終主畫師已定案。正式生圖費用須獨立核准，不借用 fusion 或 Stage2 既有預算。
- 怪物先以另張被偏好的**微Q約2.5–3頭身**候選參照，場景優先、怪物暫緩。沒有正式人審，不更新到 production。

## 2. 地面（G/T/D）的視角與拼接
1. **母材用近乎正上方的正投影／平面紋理**，材質表面不自帶近大遠小、消失點、斜攝影機、朝某角縮小的石板；允許石板塊本身不規則、局部方向性，但整體尺度均一。遊戲的 tilt/攝影機將地面壓縮呈現斜俯視。
2. **石材不是鵝卵石**：採扁平、自然不規則多邊形板石，石縫有粗墨線和少量青苔／積水，勿均勻方格／斜列／週期大亮斑；線條不必對每塊石都等厚。
3. 畫面**低對比、大筆觸、自然不規則**；保留和紙滲墨而不使細碎噪點或高反差反射搶過怪物／技能／經驗珠。新圖需與 approved Stage1/Stage2 小尺寸畫面同框對色。
4. AI 擅長畫「好看母圖」，**不要以單一輸出宣稱已無縫**。後製在不畫程序幾何假石板的前提下可對真手繪圖片作 crop、offset、patch quilting、縫線修補、切片、壓縮；**不允許用 Python/Canvas 繪幾何地面假裝真圖**。
5. 基線為 1 主材＋ 4–8 個真不同（非只有 tint）的變體＋稀疏透明 overlay；轉場 T 單獨製作，主／副材質可互通。變體任意相鄰須**四邊與角落都相容**，切勿靠固定灰色大邊框湊邊差。
6. 驗收需 **3×3 自鋪、6×6 混鋪、10×10 長距離、2D、tilt=.60 真遊戲短移動**；要看接縫、共同骨架、亮暗週期、縮放鋸齒與載入後閃跳。測試或 SHA PASS 不等於人審 `ART_PASS`。

## 3. 房屋（H）與物件（O）
- 一律**淺 3/4 斜俯視**、相同相機方位與地面接點，屋頂要可辨、不要像鳥瞰平面或正面立面，也不能每關任意換透視與光源。
- 單體 RGBA、乾淨透明外框、**腳底錨點**（候選預設 x=0.5、y=1，依實際主體調整）；畫面排序依接地 Y，接地陰影與 blur/depth 由 renderer 層處理，不先把全張圖柔焦。
- 長寬／世界尺寸以 approved 第一關房屋／玩家身高為標尺；屋舍密度稀疏、保持通路／閃招空間，不能重覆單一房屋一整排。
- 大型 props 依建築斜角；落葉、苔、積水等**地面貼花則用平面俯視**，勿錯把所有細物件都畫成斜視。
- 不把倒影、文字標籤、白底、場景地板烘在透明建築檔裡；明顯接地陰影可分層，明確標示 depth_layer。

## 4. 敵人（E/B）與 VFX
- 與玩家一致的微Q、強墨線、非寫實比例；小怪／Boss 和環境使用同世界觀。避免第一批場景母圖所附**過度Q的怪物**，不可拿來作正式人設。
- 需站姿/左右動作/受擊/攻擊等依遊戲 consumer 實際要求逐個做；同一 Boss 多姿勢需同角度、同角色比例。場景美術先完成後再輪到怪物。
- 技能與融合特效主體以核准 PNG/WebP 圖像為主，雨滴／火星等粒子僅作輔助；禁 SVG／幾何程序圖形取代美術。

## 5. 素材狀態／QA Gate
1. **視覺候選** `ART_CANDIDATE`：有 prompt、圖、尺寸、source、模型及成本 metadata，不表示合格。
2. **技術檢查** `TECH_QA`：可開圖、alpha、邊界量測、尺寸、3×3/6×6/10×10、腳底定位，測試分真值/模擬值。
3. **人審** `USER_APPROVED` 或 `ART_FAIL`：使用者核准特定圖／版本／用途；拒收稿不自動刪除，依引用安全清理。
4. **接線與遊戲** `RUNTIME_QA`：2D/.60、真跑動、Y-sort、HUD 不擋、記憶體／載入；需另授權改 runtime。僅 dev 接入也不等於正式核准。
5. **發布**：不因本規格自動觸發 commit／push／deploy，不碰音訊、TTS、BGM、KEY、環境私密資料。

## 6. 新圖檔命名與路徑（立即適用於**往後新候選**）
- **最短路徑**：`art/s1/` 至 `art/s8/`，新候選 PNG、審圖 P 圖與一份 `manifest.json` 直接放在 stage 短資料夾，**不再增設 batch/date/model/review/candidates/... 深層目錄**。
- **簡短清楚**：`g_stone_01.png`、`g_wood_01.png`、`t_stone_wood_h01.png`、`d_moss_01.png`、`h_warehouse_01.png`、`o_crate_01.png`、`e_ghost_idle_01.png`、`b_oni_atk_01.png`、`p_stone_6x6.png`。每類用途見 `art/README.md`。版本數字短而可查；不把日期、`nano_nb21`、`candidate`、長長的 stage name 寫進檔名。
- 檔名建議盡量 ≤28 個 ASCII 字元；`snake_case`。同名不覆寫，不隨便改名；`_01` → `_02` 才是下一候選，來源、provider、batch、日期、hash、審核狀態放**manifest**。
- `art/stage2-rain-port/scene/G_...png` 等**舊路徑全部保持原樣**，禁止因本規範批次重命名／移走正在被 runtime、測試、文件、manifest 引用的檔；新短路徑屬後續素材生產入口，不是立即整庫遷移。
- `art/sN/` 只存新候選，**不代表目前 game asset resolver 已支援該路徑**。日後人審核准後，另有獨立導入票做顯式映射到現有 loader/manifest。
- 不要依檔名推定 ART_PASS；除本文件外閱讀 `docs/ART_PROMPTS.md`、`docs/ART_STAGES.md`、`docs/ART_CLEANUP.md`。
