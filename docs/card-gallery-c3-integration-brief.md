## 詞庫裡真正有的欄位

單字物件有 `id`（`packId:index`）、`packId`、`jp`、`zh`、`kana`、`kanji`、`pos`、`stageIds`、`shared`。另有 `romaji`、`icon`、`example`、`cue`，這份給玩家看的模型不帶出羅馬字與 emoji，避免把它們當成讀音或插畫。

沒有 `category`。主題用 pack：有 `pack.name` 就顯示那個名字，否則標籤退回 `packId`，`source` 為 `packId`。沒有 pack 時是 `未分組`／`fallback`。沒有 `stageIds` 時分到 `未分關`。`theme` 是地景用的，不是詞彙主題，模型不用它。

`decoy: true` 的干擾項預設不進圖鑑。跨關同一 NFC 日文只留一張卡；依關卡分組時，這張卡會出現在它真實所屬的每一關下面，物件仍是同一個。

印記只讀。呼叫端把 `CARD_DELIVERY.openCards` 的結果傳進來即可。正式鍵與 `?dev=1` 的 dev 鍵沿用 C1，模型不自己開存檔、也不呼叫 `record`。讀取失敗當成 0 印，不中斷。

## 卡片狀態

| 印記 | 給畫面的狀態 |
|---|---|
| 0 | 剪影、鎖、`0/4`。不給日文、中文、假名。 |
| 1–3 | 仍是剪影與鎖，但 `1/4`、`2/4`、`3/4` 要清楚。 |
| 4 | 開卡：日文、中文、假名、漢字、詞性。插畫欄是文字「待解鎖插畫」，沒有圖路徑。 |

已開的卡排在前面，其次印記多的在前。搜尋比對卡的 `key`、假名、漢字、中文，不含羅馬字。未開的卡仍可用日文 key 找到，但畫面上只能讀 `jp`，而那個欄位是空的，不要把 `key` 印出來。預設每頁 8 張，給橫向平板約四欄、兩列的大觸控格。4000 筆的分頁測試只回該頁，不把整表交出去。

`replayRequest` 對未開的卡回 `{ ok:false, reason:"locked" }`。開卡回 `{ ok:true, event:"card-replay", jp, kana }`。

## 以後 UI 的文字線框（不是圖）

橫向全螢幕一層，不蓋住戰鬥；從暫停或結算進入，關閉後回到原畫面，不改血量與關卡。

上緣一條和紙卷軸：左狐面小標「言靈圖鑑」，中間是關卡或 pack 名稱，右上關閉。不要副標說明句。

卷軸下只有兩種篩選：依關卡、依詞包。沒有第三套自創主題。

主區是紙札格。未滿四印的札只見剪影與鎖，角上印記分數用大字。滿四印的札翻開，上方日文、下方中文，假名小一號。沒有羅馬字。札面底部若還沒有核准插畫，只放「待解鎖插畫」六個字，不畫方塊、不畫 emoji。

點開滿印的札，右側或下方一顆大紙紐寫「再聽一次」。點下去只送出 `card-replay`。這顆紐至少約 64 像素。未滿印的札不能點出讀音。

分頁是左右兩顆大箭頭加頁碼，不要長條捲軸塞滿 164 張。

## 要使用者先定的畫面

1. 詞性 `pos` 要不要出現在滿印卡上。模型有帶，因為詞庫裡真的有；可以改成不顯示。
2. 例句 `example` 目前不進模型。若要在滿印卡上讀例句，需另准。
3. 剪影要用同一張紙札壓暗，還是每詞一張尚未繪製的剪影。現在沒有剪影圖。
4. 插畫核准前，是否接受只顯示「待解鎖插畫」。
5. 一詞出現在多關時，依關卡篩選會在每一關都看到同一張卡。若只想掛在第一次出現的關，要另定規則。
6. `?depth` 無關。圖鑑不要做新的戰鬥加成。
