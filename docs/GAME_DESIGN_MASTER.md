## 1. 產品定位與核心融合

玩家是往返妖怪夜町的宅配員，以移動、衝刺及自動妖術保住燈火，在約十分鐘的一局中取件、送貨、回答日語詞義、破除首領封印，取得成長與收藏，然後帶著不同技能組合重玩。

目標玩家已會五十音，正在接觸 N5 常用詞。遊戲提供辨識、提取與間隔重遇，不宣稱完成遊戲即通過 N5，也不將四次配送收藏等同語言熟練。

| 參考來源／支柱 | 要融合的體驗 | 本作的具體實作方向 |
|---|---|---|
| Hades 第一代 | 斜角 2.5D 攝影鏡頭、可組合技能、進退與命中節奏 | 清晰腳底落點、衝刺避招、前方妖刀、讀得懂的蓄勢與收招、變異及 Duo；保持 Canvas2D |
| Vampire Survivors | 自動攻擊、短局生存、升級選擇 | 玩家專注走位與配送，升級時安全選卡；一局形成有差異的 build |
| 日本和紙水墨／半浮世繪木版／微 Q | 墨色、粗筆觸、紙感、簡練角色輪廓 | 使用真圖片與透明 sprite 序列，沿用第一關核准比例；自然低對比，危險與互動重點另保可讀 |
| 宅配日語學習 | 取件、詞義回答、封印、收藏 | 到站安心讀題，錯題回流；成功配送累積字卡，收藏不提供戰鬥能力 |

參考只限定體驗方向，不複製他作角色、圖像、關卡、介面、音樂、台詞或具體技能內容。

## 3. 單局流程與勝敗

1. 從主選單／旅路進入夜行町；讀取既有解鎖、收藏與設定。新玩家有可完成關卡的基礎選項。
2. 妖刀 Lv1 固定起手。玩家移動、轉向與衝刺，自動攻擊；靠走位決定前方斬擊與取件路線。
3. 接近取件點取得配送單，再到對應送達點答題。任務提示、地標與導航應讓玩家知道「去哪裡、送什麼」。
4. 擊敗妖怪取得經驗；升級暫停戰鬥並顯示可理解的選卡，建立技能、御守、變異及共鳴組合。
5. 經歷既有首領節點、封印題與解封戰；第一關天亮（elapsed ≥ DAWN）且擊敗終王即勝利，配送件數不設通關門檻。其他關沿用原契約。
6. 勝利結算顯示成長／配送／學習結果及本局戰鬥經過時間MM:SS（暫停不累計），只提供「回旅路地圖」按鈕且真可返回；失敗保留原三主按鈕。
7. 失敗清除局內 build，保留已成功配送的收藏與合法學習紀錄；不得誤解鎖關卡或寫入勝利。

2026-10-18使用者新定案：第一關破曉＋終王死亡，不要求六配送，也不能只撐到600秒而終王仍活著就勝利。小Boss血量為原50%（150/325/60），最終大妖鬼65%（910），其餘關卡不改。配送仍影響分數、獎勵與學習進度。局內基準約 600 秒；升級、暫停與安心讀題不計戰鬥時間，因此牆鐘時間可超過十分鐘。進關、返回、重玩與勝敗結算各自只能提交一次對應事件。

2026-10-18使用者核准首關normal難度：小怪HP×0.65、移速×0.82、時間成長×0.35且不按玩家等級追漲，spawn間隔×1.15、同屏cap57、包圍數×0.6／週期×2；升級需求每級round(原值×0.75)。既有hard曲線原樣保留為日後難度依據，不接新UI，其他關不改；Boss HP與DAWN600秒不受此profile倍率影響。今日以可玩的Stage1 MVP先發布，完整M1自然局與裝置驗收分開記錄。

## 5. Stage1 build 系統：六御守、十變異、四共鳴

以下名稱與效果為**可製作的測試原型規格**；槽位與規模是本次方向，倍率、冷卻、名稱及視效需在 M1 驗證後定稿。先以核准共用圖＋文字卡呈現，不因缺新圖停工。

### 5.1 通用被動御守

局內最多裝三種御守，與四個主動欄分開；不綁單一技能、不用收藏卡兌換。M1 先做每種一階、無隨機詞綴；已裝者不重複抽到，三槽滿後停止提供新御守，不做局中換裝系統。數值來自一份可調配置，禁止多處重複乘算。

| 原型 ID | 暫名 | 通用作用 | 必驗邊界 |
|---|---|---|---|
| `charm_power` | 力紋守 | 對已持有技能增加小幅基礎傷害 | 不改傷害來源歸屬；次級傷害不再次乘算 |
| `charm_cadence` | 疾奏守 | 小幅縮短可受修正技能的攻擊冷卻 | 保留每招下限與 Lv5 節奏；不加速 Boss／讀題計時 |
| `charm_reach` | 遠霞守 | 增加允許修正技能的作用距離／範圍 | 不放大安全區外判定；每招標示適用方式 |
| `charm_step` | 風步守 | 改善移速或衝刺周轉，採單一已測參數 | 不新增永久無敵；穿牆／落點判定不變 |
| `charm_guard` | 紙甲守 | 小幅減少承傷 | 不回油、不把所有小傷歸零；與護盾有固定結算次序 |
| `charm_gather` | 招靈守 | 擴大經驗拾取範圍 | 不增加經驗產量，不自動完成取件、配送或答題 |

與現有升級被動重複者，優先共用效果計算並明訂能否同時出現；不得把新系統變成第二套無上限倍率。御守是局內策略，永久保存僅記錄發現／解鎖，不永久疊加戰力。

### 5.2 變異：改變攻擊方式

M1 固定先做十種原型，不擴張到完整十三招內容。變異綁定已持有技能，不佔主動欄、不提升其基礎等級；同技能先以最多三個不同變異為測試容量，足以驗證散射＋追蹤＋冰封疊加。每種只取一次；與 Lv5 已具備屬性合併為單一效果，不重複複製 projectile 或控制事件。

| 原型 ID | 對象 | 行為變化 | 限制與關鍵案例 |
|---|---|---|---|
| `mut_fan` | 靈針／陰陽符 | 朝向多角度散射 | 分配每發傷害預算、數量設上限；不是免費倍增總傷 |
| `mut_seek` | 靈針／陰陽符 | 有轉向速率的追蹤 | 不瞬移、不每幀全場搜敵；失去目標可直行／失效 |
| `mut_frost` | 靈針／陰陽符 | 命中累積寒冷、達門檻短暫冰封 | Boss 抗性、重複控制衰減；Lv5 冰針合併處理 |
| `mut_pierce` | 靈針 | 改變命中後穿透路徑 | 現役已穿透則增加有限預算，不能重複命中同敵 |
| `mut_return` | 靈針 | 有限距離後折返一次 | 往返各自命中規則明示，不能再次分裂或無限回航 |
| `mut_crosscut` | 妖刀 | 延遲一次側向交叉斬 | 共用一次攻擊預算，保留前方主斬；不讓 Lv5 風刃重複派生 |
| `mut_pulse` | 靈陣 | 一次大陣拆成兩次較小脈衝 | 總傷／控制預算受限，不重置所有受擊冷卻 |
| `mut_orbit` | 狐火 | 改變環繞半徑／偏心軌道 | 不新增額外黑龍、不取消 Lv4／Lv5 特性 |
| `mut_splitblast` | 陰陽符 | 主爆後產生有限小型次爆 | 一層派生、不再黏貼、不重觸發主爆或共鳴 |
| `mut_branch` | 天狐雷 | 主目標後分出有限次級雷擊 | 次級不得再分支，不以敵人生命百分比計傷 |

第一個必做組合案例是靈針的散射＋追蹤＋冰封：三者同時生效、畫面與說明一致，敵人死亡／出界／暫停後無幽靈投射物，Boss 仍能出招。不能以「不准疊加」掩蓋狀態機問題。

`mut_splitblast` 的 M1-D-R7 工程原型（DESIGNED，未交付／非最終平衡）：每張主符主爆後在原爆心延遲0.18秒（從實際主爆開始計時，新次爆不得扣出生前的當幀時間；離散步進可稍晚觸發但不能提前），至多一次次爆，半徑為主爆快照的55%。次爆逐敵至多命中一次，對原直擊目標取主爆全傷的25%，其餘目標取主爆濺射傷的25%；均須仍在次爆範圍、存活且可受傷，因此同敵總增額不超過該符原結算角色的25%。主爆既有全傷／20%濺射、擊退、黏附與Lv1–5數量／冷卻不變，次爆不再黏貼／產符／擊退／觸發次爆或Duo。生成主符時快照傷害、半徑與變異，飛行、黏附與延遲途中升級不得回寫；暫停／選卡凍結，結束／重開清理。待發次爆硬上限32，滿額只略過新次爆、不影響主爆。boom共享三變異另票接線，不能以本票宣告十變異完整。

共享變異的 M1 工程契約（R8–R10 runtime已受控驗證，Duo／完整整合gate另驗）：`mut_fan`／`mut_seek`／`mut_frost` 各是單一全局 ID，單局只選一次，同時作用於所有已持有的適用技能；之後取得另一適用技能時沿用既有共享變異，不再抽同一 ID。維持 `BuildState.mutations` 的 flat ID 陣列，不另建逐技能副本。

每技能三變異容量依適用集合計數。新增共享變異時，所有已持有且受影響技能都須有空位；例如已持 fan＋seek＋pierce 的靈針為 3/3，陰陽符為 2/3，此時 frost 仍須排池，不能讓靈針超額。若全局已持 fan＋seek＋frost，後取得的陰陽符直接為 3/3，不能誤記為 0/3。未持有任何適用技能時不得出卡。

選卡 `skillIds` 顯示當下已持有且受影響的技能；條件／限制文字另說明共享適用範圍與取得其他適用技能後沿用。一次選卡只寫入一次全局 ID，傷害／控制各由對應技能 consumer 結算，不能重複乘上同一份加成。

共享適用分票落地紀錄：D-R8接`mut_fan`、D-R9接`mut_seek`、D-R10接`mut_frost`於陰陽符，各自真consumer驗證後才擴適用集合；不以metadata或ID齊名代替完整整合gate。R8工程原型（runtime受控驗證已收；文案／持久繼承測試與真頁整合另驗）：boom散射為原發數+2、最多6，即Lv1–5為3/4/5/6/4；沿用原相鄰角距與冷卻／速度／壽命／黏附。每cast主爆全傷與濺射傷各自分攤，使全部新符快照傷害總和不超過無散射原發數總預算（浮點誤差≤1e-9）；次爆沿用各符分攤後的25%預算，不以分攤前全傷重複派生。靈針現役fan行為不變。內部既有`mutation:needle:mut_fan`作不透明canonical choiceId保留，資格改依已持有適用技能集合，不能用前綴誤判必須持有needle；`skillIds`與可見名稱／條件顯示實際受影響技能。R8完成仍不等於三共享全部完成。

### 5.4 組合計算與可理解選卡

1. 以基礎技能等級建立攻擊描述；保留 Lv5 身分及來源 ID。
2. 對數量、形狀、追蹤、穿透與狀態效果套用已選變異；再集中結算御守修正與上限。
3. 攻擊產生時固定快照，飛行途中升級不回溯改寫既有 projectile。
4. 命中去重後處理傷害與狀態；最後檢查可觸發的共鳴。衍生事件標記來源及深度，M1 不允許二次派生再觸發。
5. 對象死亡、離場、暫停、結算及重玩時各有明確清理；讀題凍結戰鬥狀態與局內計時。

升級畫面以三選一為基線，每張顯示分類、影響技能、現在→取得後、條件及限制；不能只用稀有度顏色傳達。選項必須有效且不重複；滿欄、滿級、未解鎖、御守已滿、Duo 未合格時排除。全部耗盡時提供既有安全替代選項或繼續，不強迫玩家卡在空白升級畫面。重抽次數沿用現役規則，不在本輪引入付費或永久資源。

## 6. 狀態、平衡與防失控

新狀態以單一來源管理：寒冷累積→短暫冰封→恢復／抗性期；每個敵人同時只有一份寒冷／冰封狀態，不用疊加多個計時器延長至永久。死亡先終止控制與附著物；任何控制不能取消必要清理或 Boss 結算。

Boss 使用獨立控制抗性配置：寒冷門檻較高、冰封較短或轉為緩速，連續施加有遞減與免疫窗口。不得每次命中都重置冰封時間。確切秒數、門檻及 Boss 差異屬待測參數；是否保留短暫 Boss 硬凍須經人玩判斷。封印、無敵與劇情階段不能被新狀態略過。

平衡同時觀察清怪時間、Boss 行動機會、承傷、配送完成數、等級、選擇頻率、投射物／粒子峰值。候選倍率先保守、一次改一個主因。建立無御守／變異／Duo 基線與幾個代表 build 比較，不以全組合爆量測試代替實玩。

約十分鐘 30 級的初始觀測區間為 27–33 級，**是校準目標，不是通關條件或已通過指標**。先記錄至少三局不同 build 的完整局內時間與牆鐘時間；若超出區間，先診斷拾取、配送 XP、暫停時間及擊殺密度，再決定是否調曲線。新手勝率不預設造假的百分比，先收可追溯樣本。

## 9. 美術、鏡頭與特效規格

採 Canvas2D 偽 2.5D，預設 `tilt=0.60`、房屋 Y 間距倍率 `1.20`，保留 2D 回退及既有平滑切鏡。戰鬥世界投影與邏輯座標分離；旅路保持既有 2D，不轉 WebGL 或另起引擎。

2026-10-20 Batch1A：八關場景共用半水墨＋半浮世繪、強墨線、和紙木版與克制彩度，題材仍各關不同。地板三聯圖（左主材質／中副材質／右自然過渡）只作 A/B 概念候選，並非正式無縫 tile；第一批 ChatGPT A 組保留比較，第二批淘汰稿不用作參考但不破壞性刪除，Nano Banana 2.1 B 組待獨立付費授權。原圖不整張烘入柔焦，前中後景柔焦由 runtime 處理；正式接圖仍須另外裁切／無縫化、3×3、2D／.60 及人審。來源與逐關 prompt 見 [Batch1A 交接](ART_BATCH1A_NANOBANANA_HANDOFF_20261020.md)，A 無可證專案來源時標 `A_SOURCE_PENDING_IMPORT`，不得拿現役 tile 冒充。

1. 第一關核准現役圖是風格、腳底、角色與房屋比例基準。微 Q、強墨線、粗筆觸、和紙水墨、半浮世繪木版；避免過度寫實、密集碎細節及高飽和滿屏發光。
2. 地板、房屋、地標、道具、敵人、Boss、UI 藝術主體用正式核准 PNG／WebP。不可用程序矩形、多邊形、圓塊或 SVG 假裝正式畫；墨色塊與粗筆觸應是核准貼圖／sprite 的藝術語彙。
3. 可用透明 sprite 序列、貼圖粒子、裁切、縮放、合成、光影與受擊閃白。文字、碰撞與預設不可見 debug 為程式職責；既有真正輔助粒子保留，新 FX 優先用核准貼圖，不增加幾何假素材。
4. 地面圖不預烘斜角，由引擎投影；直立花草、房屋與角色以腳底錨點、upright、Y 排序維持體積。貼地墨痕與直立物不可混用相同壓縮方式。
5. 無縫地面須做真實 **3×3 拼接**，同時檢查上下／左右／四角、混合過渡，再看遊戲移動與切鏡。檔名 seamless、平均色接近或腳本成功不算通過；需人工看圖。
6. 候選在 `art/`，正式圖在 `assets/img/`；只有使用者明確核准的特定版本才可接 production，禁止以已有插槽／小檔／可解碼推定核准。
7. 缺圖沿用已核准回落；沒有安全對應圖則略過該藝術物件並顯示必要載入狀態，不畫新色塊。其他關尚缺新圖不阻塞 M1。
8. Stage8 骨花試貼只是隔離 dev 試驗：本機、`?dev=1&stage8preview=1`、實際 yomi 同時成立才可載候選；只允許透明單體 props，無白底矩形地景貼紙，不升正式、不影響 S1–7。

美術替換仍遵循 [真圖規範](art-asset-only-standard.md) 與 [關卡識別規範](stage-identity-standard.md)。其中舊 owner、派工、先等美術才能寫功能與舊發行條件敘述，以本次使用者指示及新製作計畫覆蓋；真圖、人審、各關獨特地景／專怪／Boss 的保護維持。

## 10. 平板、手機與手把互動

| 場景 | 必要行為 |
|---|---|
| 桌機 | 鍵鼠移動、方向、衝刺、答題與暫停沿用；不強迫滑鼠精準點小圖示 |
| 手機／平板 | 橫式為主，旋轉／安全區合理；移動區、衝刺、答題及選卡不互擋，主要操作熱區目標至少 44 CSS px |
| 手把 | 選單、三選一、答題、暫停、結算、圖鑑有可見焦點；方向可循序到達、一次按壓不重複確認 |
| 切輸入裝置 | touch／鍵鼠／手把切換後焦點與提示一致；斷線、失焦、背景返回不殘留移動或震動 |
| 資訊呈現 | 長假名與變異說明不壓扁；字體／背景有對比，危險不只靠紅綠區分，技能 FX 不蓋題板或油量 |
| 可調節 | 沿用減少動態、震動、文字與提示能力；鏡頭震動與閃光不可成為理解攻擊的唯一方法 |

手機視窗 Chrome 截圖只算瀏覽器視口驗證，不能寫成手機／iPad 實機通過。手把能操作不代表震動可用；硬體能力缺口清楚降級並列未測。

## 11. 技術、資料與 API 契約

### 11.1 沿用現有 consumer

| 層 | 現役接點 | 本次責任 |
|---|---|---|
| 關卡內容 | `CONTENT.getStage(stageId)`、`getStageWords`；`visual/enemy/pacing/world` | AGY 保持資料一致；不建立無人消費的平行 slots／boss 物件 |
| 世界／流程 | game 的 `configureStage/start`、`WORLD.createStageWorld` | Kilo 保留八關流程；Stage1 新 build 在同一底層運行 |
| 美術 | `loadStageMapArt`、`loadStageAssets`、`STAGE_ASSET_SLOTS`、renderer | 槽位必須能一路到 drawImage；只載圖不算接線 |
| Boss | 實例 `stageId/bossTheme`、`BOSS_AI.step`、STORY metadata | 真正消費主題、狀態抗性與 UI 稱號；同招式池不能說成獨特 Boss 完成 |
| UI | `UI.drawLevelUp`、`drawHud`、`drawBossQuiz`、結算／圖鑑 | Muse 渲染唯一選卡資料與 stage metadata，不自己算傷害／解鎖 |
| 保存／學習 | `STORE.createStudySession`、`STORE.finish`、現役 card delivery bridge | 冪等、正式/dev 隔離、storage 錯誤可見、舊檔不遺失 |

先前觀察到 sprite consumer 讀 `window.STAGE_ASSET_SLOTS/window.STAGE` 而定義端未對應、通用 motion atlas 覆蓋專圖、地面槽與實際 `visual.ground` 分離等風險。它們是**待現場複核的缺口**，不可只引用舊 PASS 或以本文件宣稱修好；不為本計畫重寫整個 renderer。

### 11.2 新 build 層的最小介面（現役內部 consumer 與規劃職責）

| 契約 | 最小輸入／輸出 | 強制條件 |
|---|---|---|
| `BuildState` | `schemaVersion, activeSkills, charms, mutations, duos` | stable ID、四主動含妖刀／三御守、局內與永久資料分離 |
| `getEligibleChoices` | build＋已解鎖集合＋可注入 RNG → choice 列表 | 排除無效／重複／未解鎖，無有效選項有降級 |
| `applyChoice` | choiceId＋目前 revision → 新狀態／拒絕原因 | 重新驗資格、重複確認只套用一次、UI 不可直接寫技能資料 |
| `resolveAttackSpec` | skillId＋等級＋build → 攻擊快照 | 集中順序與上限；不改無變異 Lv5 基線 |
| `resolveHit/Status` | attackId、targetId、source、派生深度 → 傷害／狀態事件 | 去重、單層派生、Boss 抗性、生命週期清理 |
| `ChoiceViewModel` | id、分類、技能、前後描述、條件、可用原因 | Muse 不需重新解析判定；支援鍵鼠／觸控／手把 |
| `recordFirstClearUnlock` | stageId＋勝利結果 → 新解鎖／已領取／保存失敗 | 首通一次、舊檔遷移、沒有未解鎖卡阻塞 |

前四項已由M1-A～D接入game內部runtime並分票驗證，不表示公開全域API；resolveHit/Status、recordFirstClearUnlock仍是職責名稱，沿用既有hurt/applyFrost與STORE.finish等consumer，不要求新增空包裝或永久build schema。以上實作可直接擴充既有函式；不得為每個名稱新增模組／服務或建第二套引擎。由製作計畫指定的現行 runtime writer 提供確切函式與檔案位置、資料 owner 對齊定義、Muse 消費同一 view model，接口交接後才寫入；暫時改派以 AGENTS／製作計畫／roadmap 的最新交接為準。

新存檔欄位採加法與版本遷移；未知 ID 忽略並保留合法資料，缺欄採安全預設。M1 不承諾中途關閉後恢復整局；不引入雲端同步、帳號、後端、付費 SDK 或外部 AI API。測試以離線 deterministic RNG／stub 完成，禁止讀 KEY 或呼叫 TTS／BGM／真聲檔。

## 12. QA 與成功指標

| 層級 | 完成條件 | 必須留下的證據 |
|---|---|---|

| 自然遊玩 | 至少三種代表 build 完整走局，分列局內／牆鐘時間、等級、配送及死因 | 真人／受控腳本／加速分開標記；保留可重現問題 |

Stage1 切片成功看五件事：玩家能獨立完成一次配送；能說出至少兩種 build 的差異；不用指定掉落也能完成；重玩可自然形成不同組合；十分鐘內戰鬥、讀題、選卡與性能沒有阻塞。初始效能目標為目標裝置穩定接近 60 FPS、P95 frame time 以 20 ms 為觀測門檻；未達先定位，是否接受 30 FPS 降級必須明確記錄與決策，不把估算當實測。

必測高風險組合：散射＋追蹤＋冰封、Lv5 冰針疊冰、符咒主爆／次爆與 Duo、黑龍焦土與餘燼、Boss 封印／半血／死亡、升級連按、暫停／重玩、storage 拒絕與舊檔。測試依變更風險聚焦，不以覆蓋率或全排列數量當里程碑。

## 13. 非目標、風險與待審

非目標：本輪不重建八套遊戲、不先補全八關正式圖／聲包、不換引擎、不做 Hades 房間制、多人、商城、無限永久強化、完整語法課、程序假美術、全新十三招一次上線，也不部署。

| 風險／待決 | 處理方式 | 阻塞範圍 |
|---|---|---|
| 新系統與現役 Lv5／既有被動重複 | 鎖無變異基線、集中計算、先做代表疊加案例 | 相應原型，非整季 |
| 散射／追蹤／冰封過強與計算暴增 | 數量、命中、派生、控制與索敵預算；Boss 抗凍 | M1 組合驗收 |
| 新 FX 未有核准圖 | 共用核准回落／文字；新候選另審 | M2 最終視覺，不阻 M1 |
| S7/8 候選偏寫實、Stage8 白底拼貼 | 保留待修，不升正式；dev 隔離與透明單體驗證 | 對應 M5 圖包 |
| 「每關解鎖」與 13 招數量不一致 | 暫按 S1–7 七次新招規劃；S8 獎勵待使用者決定 | 後續終章獎勵，不阻 M1 |
| 新招內容／原型數值未經人玩 | 明列測試配置，選卡效果可觀察後再定稿 | 個別內容正式放行 |
| 30 級／勝率／性能無實機樣本 | 自然局先量測、真機另驗；不編造數據 | M3／平衡定稿 |
| 350+ dirty 與多人 writer | 白名單檔案、交接快照、不清理別人改動 | 衝突檔暫停，其他路徑繼續 |
| 音訊與 KEY 凍結 | 不讀、不測、不改；測試先 stub／阻擋 | M6 等使用者明確解凍 |

正式人審包含：新圖片與 FX、原型效果可讀性與平衡、七種新妖術內容、S8 獎勵、裝置降級取捨、音訊解凍與最終發布。已授權的 Stage1 程式原型可持續推進，不以每個可逆細節另求批准。
