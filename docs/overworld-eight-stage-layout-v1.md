## 1. 現況核對

- 現行旅路程式位於 js/overworld.js：1800×1050 世界地圖、900×600 基準視野，五個正式 stage、四個 waypoint。
- 當前道路繪製為**節點中心之間的直線**；角色每段位移約限制在 0.42–0.72 秒。把八關直接長距離連起來會跳躍感過強，需要合理加入中間 waypoint。
- 現行名稱牌約 208×46，位於節點中心下 y+43；地圖小角色高約 108，置於 stage 中心附近偏左 x−75、偏下 y+23。
- 目前 HUD：上方固定標題約 y0–80、底部資訊板 x260–640/y484–584、右下出發按鈕 x768–880/y512–574。
- 現有通關解鎖寫在 js/store.js：夜行町 → 雨夜港町 → 妖櫻山道 → 百鬼京都 → 黃泉境。**未來實裝八關時**要插入第 4、6、7 關，保留原有五關 ID 與舊存檔進度。**本輪未修改程式。**

## 2. 建議構圖（座標未經核准）

## 3. 主線道路與過渡點

建議 **8 個 stage ＋ 9 個 waypoint（共 17 個節點，16 段路）**。四個舊 waypoint ID 保留，另增五個過渡點（並非五個新關卡）。

正式主線依序：

1. 旅立ち gate（180,1210）→ **夜行町**
2. 分かれ道 cross-west（565,1220）→ **雨夜港町**
3. 港後坡 port-rise（910,1150）→ **妖櫻山道**
4. 古道 cross-east（1220,830）→ **竹影迷宮**
5. 竹林出口 bamboo-exit（1520,845）→ **百鬼京都**
6. 見晴台 lookout（1900,780）→ **雪燈山寺**
7. 雪路 snow-pass（2260,740）→ **幽世渡口**
8. 幽河彼岸 yomi-ford（2585,770）→ 黃泉斜坡 yomi-ascent（2675,545）→ **黃泉境**

為什麼改路線：原本分岔可以在雨夜港通關前直向妖櫻，未來若八關是明確順序主線，容易產生未解鎖路徑或倒走問題。改成依劇情順序移動，分岔點仍保留為視覺節點，日後可外接**不影響通關**的純風景探索路線。

**本稿尚未直接改動 NODES、EDGES、STORE、地圖移動速度或攝影機實作。** 只有規劃未來路網；正式進 A5 時還需驗證解鎖條件、路徑搜尋以及舊玩家地圖存檔行為。

## 4. 地景留白、安全區及視覺層

- 每個正式關卡中心附近暫留**約 264×250 的低干擾構圖區**（地形／建築自然留白，不是真的畫一塊方形或圓形平台）。
- **純背景不可烘焙** UI、角色、關卡名、文字、關卡編號、節點圖示、鎖定標記、發光虛線道路。定位 HTML 中的這些元素都是**示意的程式疊加層**。
- 主視覺地標不要被關卡圖示和名稱牌完全遮住；地圖按章節與區域有鮮明的輪廓、色彩與 Q 版水墨細節。
- 使用者第二張設計圖是**美術母版**，需在真正美術階段作為圖片輸入參考，而不能只文字描述其風格；如果參考圖沒有存到專案，新一輪請先取得原圖。
- 逐關攝影機 900×600 的中心畫面在本定位稿中已依 clamp 規則計算。計算上這八關的名稱牌均不直接壓在底部資訊板上；**仍需 A2 的真實遊戲渲染與行動裝置驗證**。
