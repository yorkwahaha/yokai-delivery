## 1. 每關必須不同

每一關都要同時具備下面五種自己的東西：

1. 地板材質
2. 整體場景
3. 建築物
4. 裝飾品
5. 辨識地標

配樂由使用者按關另選、另提供。Agent 不准生成新曲，也不准替換現有 `assets/audio/BGM.mp3`、`MAP.mp3`、`BOSS.mp3`。

不合格的差異：

- 只改色調、霧、花瓣數量、螢火數量。
- 只換詞庫或 Boss 稱號字串。
- 全關使用同一組敵人圖，以及同一張 Boss 圖、同一套攻擊。
- 只改 `speedScale`、`shooterChance`、`bossHpScale` 這類數字。

可以保留一部分共通怪，讓世界觀連續。每一關仍要有新鮮感：至少一種該關專用的新敵人，以及一隻專屬 Boss。

專用敵人與專屬 Boss 都要有：

- 高品質手繪 sprite（PNG 或 WebP）
- 一眼能分開的輪廓
- 至少一個差異化的行為、技能、移動或攻擊

禁止為了省美術而用 Canvas、SVG、HTML、CSS 的矩形或多邊形當敵人、Boss、地板、房屋、裝飾或地標。

第 3–8 關現在只建立待設計欄。沒有使用者核准的圖與行為之前，禁止寫成已完成。

## 2. 功能共用與素材重用

| | 可以共用 | 不可以當成該關識別 |
|---|---|---|
| 功能 | 碰撞、追擊骨架、文字題、傷害結算、鏡頭與 2.5D 投影 | 把「會追人」本身說成該關新行為 |
| 素材 | 使用者點名可留的共通怪圖 | 地板、場景、房屋、裝飾、地標、該關專用敵人圖、Boss 圖、該關配樂檔互相複製 |

驗收時要能指出：兩關並排，地板、房屋、地標、專用敵人輪廓、Boss 輪廓都不是同一張圖。只改縮放、色調或檔名不算新圖。

### 3.4 第二關敵人與 Boss：證據與方案

只讀結果：

- `js/words.js` 的 `rain-port.enemy.bossTheme` 值是 `"harbor"`。全檔只有這一關有這個欄位。
- `js/game.js` 約 2166–2168 行用這個字串決定稱號後備字「港霧大妖」。`js/story-dialogue.js` 已寫 `bossTitle: "港霧大妖"`。稱號不是 sprite。
- `js/renderer.js` 約 777–778 行：只要 `type === "boss"` 就畫 `window.ART.boss`。沒有依 `stageId` 或 `bossTheme` 換圖。
- `js/boss-ai.js` `nextAttackKind`：tide 只在 `stageId === "rain-port"` 且是終王時加入。這是行為差異，不是新外形。其他關終王沒有 tide。港町的門番與中波仍是 slam／charge 這一支共用邏輯。
- 小怪種類與第一關相同，只是第二關允許 shooter，機率 0.06。

因此：**已有 `harbor` 字串不等於真正的新 Boss sprite。** 現有 tide 只掛在終王邏輯上，沒有專屬圖，第二關敵人與 Boss 尚未完成。

完成標準是實作加驗收，不是「有方案即可部署」：

1. 至少 1 個正式新增的手繪小怪 sprite。輪廓和 ghost、runner、tank、shooter、Boss 都不同。追擊或攻擊行為必須和共通怪不同，不能只改 `shooterChance` 或血量。
2. 至少 1 個手繪專屬 Boss sprite，加上該 Boss 自己的技能。潮汐攻擊要接在這隻 Boss 上。禁止繼續用 `ART.boss` 充當港霧大妖。中間波次也不能只留大妖鬼的圖。
3. 上述兩者都要進入遊戲：生成、資產載入、繪製、AI。自動測試與視覺驗收都要過。
4. ghost、runner、tank 可以少量留下，當作共通怪。
5. 現在沒有已核准的小怪圖與 Boss 圖。【BLOCKED】先請使用者核准造型。核准前禁止批量生圖，也禁止改 `js/` 用幾何圖頂替。

造型核准後的接入路徑（仍須另行授權，一次只改被點名的檔）：

1. 新圖另存，不覆蓋 `assets/img/boss.webp` 與 `assets/img/rain-port/` 既有檔。
2. 資產載入按 `stageId` 進關才取圖，作法對齊現有 `refreshPortArt()`。缺圖時不畫幾何身體。
3. `spawnEnemy` 增加該關種類，行為不要只寫進 `shooterChance`。
4. `drawEnemy` 依種類選 sprite，Boss 不再無條件用 `ART.boss`。
5. tide 繼續只放在雨夜港町終王，不複製到其他關來假裝每關都有新招。

## 4. 配樂預留

現役只有三條全域音軌，沒有 `stageId` 對應表：

| 物件 | 檔 | 行為 |
|---|---|---|
| `window.BGM` | `assets/audio/BGM.mp3` | 所有戰鬥關共用 |
| `window.MAP_BGM` | `assets/audio/MAP.mp3` | 旅路 |
| `window.BOSS_BGM` | `assets/audio/BOSS.mp3` | 只有終王破封才 `startBossMusic()`（`js/game.js` `answerBoss`，`bs.final`） |

漸變已存在於全域 Boss 曲：`bossMix` 以約 1.1 秒從戰鬥曲混到 Boss 曲（`js/audio.js` `updateBgm`）。缺檔時 `error` 把該 Audio 設成 null；三條都沒有時，`assets.js` 會落到內建程序和風合成。

之後要預留、現在還不寫進程式的契約：

| 欄位 | 規則 |
|---|---|
| `stageId → 探索曲` | 每關一個獨立槽，狀態是待選。使用者交付前不得改 `BGM.mp3`。暫播現役曲只是為了遊戲不斷音 |
| `stageId → Boss 曲` | 同樣每關一個待選槽。使用者交付前不得改 `BOSS.mp3` |
| 漸變 | 使用者交檔並接入之後，沿用約 1.1 秒交叉。切關換該關探索曲，終王破封才換該關 Boss 曲 |
| 快取 | 新檔接入時走既有媒體雜湊。本輪不改 `service-worker.js` |
| 缺檔 | 槽是空的，或載入失敗：該槽保持 null，暫播現役全域曲，遊戲不中斷。禁止生成新曲，禁止程序配樂冒充該關主題曲 |

八個 `stageId` 的探索曲與 Boss 曲目前都是空的。**配樂最終驗收：待使用者交付。暫播同一首現役曲不算通過。**

部署時怎麼處理：現役 `BGM.mp3`、`MAP.mp3`、`BOSS.mp3` 保持不動。發佈紀錄必須寫「每關配樂待使用者交付，最終驗收未過」。使用者把檔交給對應 `stageId` 槽並完成接入與試聽之前，不得把配樂勾成完成。這項不把「有方案」或「暫播同曲」寫成部署已通過。

## 5. 驗收門檻

每一關標完成之前，要同時成立：

1. 地板、場景、建築、裝飾、地標都有該關自己的手繪圖，不是色調濾鏡，也不是另一關的同圖。
2. 至少一種專用敵人：新 sprite、新輪廓、一個非數值行為。
3. 專屬 Boss：新 sprite、新輪廓、至少一個非數值行為。稱號字串、`bossTheme`、血量與速度不算。
4. 共通怪若保留，清單要寫明，而且不能讓該關畫面上只剩共通怪。
5. 配樂最終驗收要有使用者交付並接入的該關曲。槽位待選可以暫播現役曲，但同曲不算該關完成。Agent 自己生成或替換現役曲不合格。
6. 正式畫面沒有敵人、Boss、房屋、地板的程序幾何。
7. 連續截圖能並排看出與相鄰關不同。測試數字另記，不代替這條。
