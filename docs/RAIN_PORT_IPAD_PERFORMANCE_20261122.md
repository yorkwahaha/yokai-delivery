## 2026-11-23｜空中粒子同場對照與修正

第二份 iPad JSON 的第 763 秒定格有 47 敵、84 顆靈玉、380 粒子。主畫布 1762×1177，地面重畫計數維持 2441。A → P → A → P 重複出現下列差距。

| 條件 | rAF FPS | rAF P95 | JS 回呼 P50 | 回呼外 P50 | 空中貼圖／幀 |
| --- | ---: | ---: | ---: | ---: | ---: |
| A 完整畫面 | 35.6–37.8 | 29–32 ms | 4 ms | 22–24 ms | 333 |
| P 隔離空中粒子 | 55.2–58.1 | 18–20 ms | 2 ms | 15–16 ms | 0 |

P 的滿 600 幀視窗維持 56.0–56.5 FPS，短窗最高 58.1。地面粒子始終約 7 次貼圖／幀。A 的 333 次貼圖約有 121 次用非預設混色，估算約 68 萬裁至畫布內的矩形像素。這是本次掉幀情境中已驗證的主要繪製負擔。報表顯示這部 Safari 的三個 Canvas 都無原生 filter，排除了前版計數器誤記的整畫布濾鏡訊號。GPU 各階段耗時仍無法從報表分解。

- `js/fx.js` 讓雨港空中粒子同一形狀／顏色共用一個已完成的 `ImageBitmap`。轉換前與失敗時沿用原 Canvas，成功則替換共用來源，現存粒子一起換到新來源。匯出新增 bitmap 成功、等待、失敗數。WebKit 原始碼中，畫 Canvas 會先從來源取得原生影像，`ImageBitmap` 則使用已建立的 backing buffer。實測裝置上的各自成本仍需比較。 [WebKit Canvas 2D 實作](https://raw.githubusercontent.com/WebKit/WebKit/main/Source/WebCore/html/canvas/CanvasRenderingContext2DBase.cpp)
- 同模組合併直立校正與局部旋轉／壓縮，未旋轉的粒子直接算目的四邊。按原順序繪製，透明度、混色、動畫、形狀、色彩、大小、數量與優先順序沿用。診斷 P 保持原用途，正常模式仍顯示全部粒子。
- Chromium 同場比較 380 顆混合形狀與混色，前後都是 380 次貼圖。2.5D 的 Canvas 變換與 save／restore 指令從 3,145 降到 989。2D／2.5D 各比較合併變換與 bitmap 後的 RGBA，差異像素低於 0.5%，最大單色通道差 2／255。可用 `node tools/measure-port-performance.cjs --verify-particle-pixels` 重跑。
- Windows 雨港同場 380 顆粒子的前後兩組短測，JS 回呼 P50 從 2.8–2.9 ms 到 2.1–2.2 ms，FPS 都約 60。共用 bitmap 就緒 6 個、等待 0、失敗 0。聚焦測試 91 項通過，現行集合 1,186 通過、8 項既有 V3 失敗、1 TODO。未提交、推送或部署。
- 回退 bitmap 可取消 `sprite` 的轉換，保留原共用 Canvas。合併變換可獨立回退到原 `paint` 與 `drawLayer`。下一次 iPad 先以 H、100% 解析度完整遊玩到第 12–16 分鐘，P 保持關閉。匯出的 `bitmapSprites` 可辨認裝置實際使用哪條路徑，45 FPS 仍以這次完整畫質的裝置結果驗收。

## iPad 回傳資料

第三局從約第 3 分鐘的中位 57.4 FPS 降到第 10 分鐘約 35.2、第 12 分鐘約 29.1。第 824 秒錄到 26.25 FPS，該視窗 JS 回呼 P50 6 ms、回呼外 P50 29 ms，回呼 P95 則達 21 ms。通關過場隨敵人和特效退場回升，敵人歸零後約 55 FPS，最後結算近 59 FPS。這份資料沒有 Canvas context loss。後段載入圖數停在 114，抽卡留存上限仍為 10。Safari 報表沒有 JS heap，因此這些觀測無法排除程序或 GPU 記憶體壓力。

第 744 秒定格有 58 敵、22 顆靈玉、365 粒子，且 Lv5 靈陣生效。在這段，A 與 G 的 JS 回呼 P50 同為約 4 ms。G 的 rAF P50 由約 31 ms 拉到 49–52 ms，主要增加在回呼外。G 一起改變主畫布呈現比例和地面 backing store，每次切換只有一次地面重畫。故 G 可重現退化，個別縮放／取樣、合成路徑與溫控的占比仍未驗證。正式畫質保持 100%。

第 664 秒的 E 53 顆與 E 512 顆短窗約 27.7 和 23–25 FPS，512 顆較重，少量靈玉時已經有低 FPS。第 744 秒的 A、B、D 持續在 32–34 FPS，且地面重畫計數在這幾組持平。這些條件降低了靈玉、靈陣或當下地圖重畫單獨解釋長期下降的可能性。低 FPS 也出現在關掉繪圖抽樣的時段。

後段詳細抽樣平均每幀約有 221 次空中粒子貼圖。新增 **P** 只隔離這些粒子的貼圖，保留粒子狀態、地面粒子、雷電描線和其他場景。下一次掉幀可固定在 100% 解析度，以 **A → P → A** 比對每組約 20 秒。匯出會保留各條件的詳細繪圖摘要。新報表也列出 Canvas 是否原生支援 filter 和讀到的有效設定。舊檔中幾乎所有主畫布圖片都標為 filtered，當時無法排除讀到瀏覽器不執行的 JS 自訂欄位。

Windows 受控驗證以 `node tools/measure-port-performance.cjs --brief A P` 固定 365 顆空中粒子。P 將該 pass 的貼圖指令由 365 降至 0，兩組地面技能各保留一次貼圖，兩組 rAF 都約 60 FPS。這確認了隔離範圍，iPad P 的 FPS 仍待量測。此輪聚焦 94 項通過，現行集合 1,183 通過、8 項既有 V3 失敗、1 TODO。

## 開發模式與報表

- 本機 `?perf=1`。同一區網測試使用 `?perf=1&dev=1&s3play=1&stage=rain-port`，走既有隔離的開發存檔。公開網站無法啟用此診斷。底部「效能實驗」可直接選條件，下載 JSON 只由使用者觸發。
- 每次 rAF 記時，滾動 600 個有效幀。隱藏頁面、切條件及詳細 Canvas 抽樣周圍的間隔會排除。JSON 同時有最近間隔、分場景時間、update／world Canvas／UI／特效區段時間。特效區段計在 world 內。快照每 5 秒一次，保留最近 246 筆。遊戲時間、Boss 招名及階段、移動和近期技能施放可與幀時間對照。
- 「抽樣繪圖指令」約每 60 幀計一次。分類包括地圖、場景、敵人、粒子、靈玉、彈幕、傷害文字等。圖片統計使用套用變換後、裁到 backing store 的矩形面積，不含透明像素遮罩、Path 剪裁、GPU 實際顯存或提交完成時間。數值適合比較相同場景的負擔。以關閉此選項的視窗比較 FPS。
- 快照還包含地面重繪／scroll copy／context lost 次數、Canvas 尺寸、已就緒影像與估算像素、卡片／粒子／chunk 快取、技能暫態與平台有提供的 JS heap。Resource Timing 統計回應耗時和傳輸量。`await YOKAI_PERF.probeDecode()` 可額外量測靈陣圖 `decode()` promise 響應，已暖機時可能立即完成。這些是本頁可觀察到的載入與保留指標。
- 如有可連線的 Mac，在 iPad 掉幀當下錄一段 10 秒的 Safari Frames Timeline，並比對 JavaScript、Layout、Paint 和 Other。若 A、B、G 幀間隔接近而 callback 仍短，再檢查同一時段的 Safari 或裝置排程。 [Apple iPad Web Inspector](https://developer.apple.com/documentation/safari-developer-tools/inspecting-ios) [WebKit Timelines](https://webkit.org/web-inspector/timelines-tab/)

`tools/measure-port-performance.cjs` 使用 Playwright 的本機路由讀取專案檔。可用 `--baseline --brief A E512 A2` 與 `--brief A E512 A2` 做同條件比較。`--verify-pixels` 比較 2D／2.5D 與 53／512 顆的同幀 Canvas RGBA。執行 `H` 會在同一固定港景中繪製 20 分鐘。實驗不登入、不安裝瀏覽器、也不模擬玩家操作。需要時用 `YOKAI_BENCH_CHROME` 指定現有 Chrome 執行檔。

## iPad 最短驗收

1. 橫放、Safari 保持前景，開啟同網路的區網預覽。選「開發選關 → 直接進關」。用 H 實玩，關閉詳細繪圖抽樣。記錄 iPad 型號、iPadOS 和低耗電模式。
2. 低於 45 FPS 且巨大靈陣可見時，依序選 A → D → B → G 75% → A，各留約 20 秒，保持同一場景。若沒有看到靈陣，以 F Lv5 先驗證該特效，並另外保留真實 H 記錄。A 前後一致才用中間數值推論。
3. 切回 H，完成原本的關卡。可在結算畫面保持同頁到第 20 分鐘，方便比較資源回收。通關後下載診斷 JSON，補記雨滴、背景、閃退及畫面手感。
