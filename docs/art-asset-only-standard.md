## 1. 畫風與精細度

- 半水墨，加上半浮世繪。
- 強墨線。
- 和紙木版質感。
- 視角、比例、墨線、質感沿用已核准第一關雛形。現役町屋檔是 `assets/img/house_shop.png`、`assets/img/house_tavern.png`、`assets/img/house_shrine.png`，以及 `assets/img/scenery/` 下同名 WebP。精細度以這些雛形為下限。
- 已核准旅路背景 `assets/img/overworld_approved_v2.webp` 不在這條命令裡重製。
- 白色幾何方塊、純色矩形路面、程序木板線，都不合格。
- 測試通過數、WebP 檔頭合法、位元組大小，都不能冒充美術合格。

## 2. 八條標準

1. **全部正式可見物件與 UI 藝術主體圖片化。** 房屋、路面、道具、招牌底板、裝飾、UI 藝術主體都必須是 PNG 或 WebP。不得用 SVG，也不得用程序繪製的矩形、多邊形、線條或形狀代替美術。
2. **真圖像才算畫圖。** 素材來自手繪或真正的圖像生成。程式只許裁切、縮放、壓縮與 `drawImage` 擺放。禁止 Pillow、JS、SVG 畫出幾何圖再假裝是手繪。
3. **沿用核准第一關的視角、比例、墨線、質感。** 新圖要能放進現有 0.60 傾角與房屋腳底排序，不得把傾斜預烘進地面貼圖。
4. **缺圖不得用色塊 fallback 偷渡。** 圖未載入時，正式畫面不畫假房子、假路面、假道具、假招牌底板。可以保持空白或停在載入。不可見的碰撞與 debug 框可以留著。
5. **准許粒子、文字、碰撞與可隱藏 debug。** 雨水、火花這類輔助粒子仍由程式繪製。假名、HUD 文字、傷害數字仍是文字排版。碰撞盒與預設關閉的 debug 框不是美術主體。
6. **圖片級人工審與連續截圖才算驗收。** 審的人要看到圖本身，以及冷啟動、切鏡、進第二關的連續畫面。19/19、603/603、88/88 只證明程式契約，不證明美術。
7. **不確定先上問。** 需求、素材來源或破壞性替換不清楚時，停止該部分，並用下方格式上報。其他已經明確、且不碰到他人檔案的工作繼續。
8. **其他 Agent 同時工作不得改重疊檔。** 動工前用 `herdr agent list` 看現場，不沿用舊 paneID。本輪規範檔只由 Grok 寫。

## 3. 程式允許與禁止

允許：

- `drawImage` 置入已經存在的 PNG／WebP。
- 裁切、縮放、壓縮、透明邊緣清理。
- 投影、2.5D、`upright`、分層、Y 排序、相機。
- 碰撞與預設不可見的 debug 框。
- 文字排版。
- 雨水、火花等真正輔助粒子。

禁止出現在正式可見畫面上：

- Canvas `fillRect`、`strokeRect`、`roundRect`、多邊形、圓、線段，用來充當房屋、路面、道具、招牌底板、裝飾或 UI 藝術主體。
- SVG、HTML、CSS 的形狀美術，含現役 `assets/img/ui/awaken_seal.svg` 這一類正式可見圖。
- 缺圖時的色塊、條紋木板、白色幾何房子。
- 用影像函式庫或腳本「畫」出一張假手繪再存成 WebP。

文字筆畫、粒子、碰撞與隱藏 debug 不在這條禁止裡。

## 6. P0 驗收守門：第一關地板拼接

使用者回報：第一關地板在初次載入，以及切鏡之後，會有數秒拼接不正常，然後才恢復。這與已完成的「P0 傾角決策」不是同一項。

守門（必須全部成立才可把這一項標 `[x]`）：

1. 冷啟動進入夜行町，從第一幀到畫面穩定，地板拼接保持同一張正確的圖。不得先錯數秒再變對。
2. 鏡頭大幅移動，以及 2D／2.5D 切換之後，同樣不得出現數秒錯拼。
3. 證據是連續錄影或連續截圖，包含錯拼會出現的那幾秒。單張「已經正常」的圖不算。
4. Node 測試通過數不算這項通過。
5. 修復時仍禁止用色塊或程序矩形蓋住錯拼。
