新雙層 Roguelite 為後續方向，**前兩關未完整可玩時不實作委託與路線**。U1 候選可先選圖，但正式選單底圖更換應避開 F1–F4 封版衝突。Stage3–8 原有入口、字池與存檔須保留。當前不授權任何 production 派工、提交或發布。

## 3. 每個階段的下一張有界工單

**F1：先取工作樹／Hash 基線。** 唯一 resolver 和 normal URL 真消費端（game, renderer, UI, VFX）對照六技能、十融合、Boss 與兩關；解決路徑歧異及 DEV 候選外漏；港區地板的來源接縫有根因才調整，勿盲改 renderer。

**F2：逐一強制真功能。** Boss 六類 telegraph／active／recovery、原 hitbox、可見圖與動畫；十種融合都走兩母技 Lv5 → offer → confirm → replace → 攻擊／異常 → HUD／死亡清除。玩家能看到真正技能圖與明確效果，沒有純幾何主圖替代。反例須含選不了、重複點、滿槽、丟失圖片、暫停與重開。

**F3：兩關可見修整。** Stage1/2 各一包地板與建築密度/方向/遮擋/角色陰影、跑動步頻配速度但不抖動；雨港海面/碼頭/店面/載圖與接縫；配送相距過短與下一單不生成、20單連續驗證；各選單實際操作與音訊不中斷。既有UI局部 19/19 不等於真遊戲同版 PASS。

**F4：固定版 Gate。** QA runner 先接受故意404、wrong origin、錯關、缺decode、失敗卻硬PASS等負例；再固定五大檔與 manifest SHA，八格真頁與兩關自然長局分開收集。正常遊玩不可使用瞬移或跳時冒充全通；裝置未到就實報。

**U1：換圖不換遊戲規則。** 捲軸新底板採端部獨立切片、中段可延展、乾淨和紙內容層；選卡資訊動態繪製。選單 UI 候選與人審先行，F4 後才正式貼回共同主線。

**R1–R3：先 Stage1 MVP 再 Stage2。** 先三委託各一種額外目標；再三局內路線各一個事件；再九格差異化/平衡；所有原勝敗、Boss、日語配送、字卡與既有 save 保護，預設未啟用。數值／價格／獎勵事件頻率需人玩再定。

## 4. 每階段一張交卷收據

建議收據路徑：docs/delivery-reports/PHASE-ID-YYYYMMDD.md；每張使用相同欄位：

| 欄位 | 必填資訊 |
|---|---|
| 階段、owner、狀態 | NOT_STARTED／IN_PROGRESS／PARTIAL／BLOCKED／PASS／USER_REVIEW_PENDING |
| 玩家可見交付 | 這輪實際已完成的畫面／玩法；尚欠項逐條列，不用模糊百分比 |
| 工作樹證據 | HEAD、差異白名單、dirty 狀態、測試前後SHA；DEV/normal版本一致性 |
| 驗收結果 | 測試命令exit／案例分母；Chrome尺寸、tilt；截圖/錄影/raw；自然局與fixture分開 |
| Gate逐條判斷 | PASS／FAIL／NOT_RUN，阻塞 P0/P1/P2 與根因／如何重現 |
| 下一步 | **只有一張**當前可開的最小工程票、writer、依賴、預期成果 |
| 人審、發布 | 待使用者決定圖或平衡；是否獲得commit/push/deploy核准（預設否） |

節奏為：小工作包停筆 → 聚焦 QA → root 固定同版核證 → 更新收據及 roadmap 頂部 → Gate PASS 才進下一階段。沒有通過就給原 owner 一張有界退修票，不重派「全部繼續」讓進度失焦。

2026-10-26 僅把本文件、雙層遊戲企劃與索引文件寫進工作樹。未動 production／測試／資產／音訊與任何存檔，不解除原 writer 凍結；不 commit、push、deploy。當前 F1–F4 仍是最先需要執行的主線。
